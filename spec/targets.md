## AWS

VPC-bound and regulated deployments, and teams already operating on AWS.

The `lambda-fargate` target runs reconciliation in Lambda, dispatches ECS tasks through Step Functions, and hosts the native Linux `contextful-full` executable in Fargate containers. The query process embeds DuckDB; component execution embeds Wasmtime. RDS Postgres supplies the shared catalog and S3 holds corpus objects. The `fargate-daemon` alternative keeps scheduling and reconciliation in the native daemon.

## Cloudflare

Edge-first deployments on native object storage with near-zero idle cost.

The default `worker-container-d1` target places TypeScript routing and reconciliation in Workers' V8 isolates, with Cron Triggers and Workflows as the scheduling and orchestration services. A Durable Object controls a Linux Container's lifecycle. Inside that Container, the native `contextful-full` executable runs the Rust engine, embedded DuckDB and embedded Wasmtime; Workers and Workflows reach it across a request boundary.

The Rust processes use `CONTEXTFUL_STORAGE_PROFILE=cloudflare-d1`. Requests to the private `contextful.d1` outbound host reach a Worker binding handler, which accesses D1 for execution metadata and an R2 bucket for execution blobs. Corpus parts and manifests occupy a separate R2 bucket through its S3-compatible API; Container files form a replaceable local working copy. The `worker-container` alternative assigns the catalog role to Durable Object SQLite instead of D1.

Cloudflare Queues carries receive batches and object-arrival notifications; the Rust engine remains the store writer. A separate Durable Object owns the hibernating WebSocket projection. Workers Secrets supply credentials to the configured bindings. The optional Node.js console server requires its own Node-capable host; its React assets alone form a static browser preview.

The execution binding example under `apps/cloudflare-execution/` exposes authenticated `POST /conformance`: its Container runs `contextful-conformance`, which drives the packaged Linux `contextful` binary. That example's endpoint is a conformance harness, distinct from the target's query and orchestration routes. Clause implementation evidence lives in `status.md`.

## Linux (reference)

Self-hosted Linux servers, development, and air-gapped single-node deployments.

The `contextful-full` Linux executable runs natively on x86-64 or ARM64, using the corresponding `x86_64-unknown-linux-musl` or `aarch64-unknown-linux-musl` release artifact. A long-lived `contextful pipeline serve` process owns the scheduler and launches the same executable as `contextful pipeline run` or `contextful job fire` children. A separate `contextful serve` process answers MCP and HTTP requests. A service manager such as systemd supervises these processes with the same project working directory and configured environment.

Wasmtime executes WebAssembly component connectors inside a run child; its Tokio runtime is embedded there. DuckDB executes SQL inside the process serving reads. SQLite is an embedded library for execution state, with files such as `machine.sqlite`; Parquet parts, manifests and control snapshots live under the project's configured filesystem root. These libraries have no separate service process.

The optional operator console is a separate Node.js 22 process, `node apps/console/dist/server.js --http <host:port>`, and reaches the Rust HTTP server through its configured store endpoint. The browser executes the React client. The local target uses the filesystem receive spool; bucket sync adds an explicitly configured S3-compatible endpoint.

The repository's Dockerfile packages the Linux executable in a shell-free, non-root image with `/data` as its project volume. Separate scheduler and HTTP containers share that persistent volume. On macOS, a Darwin executable runs the same process layout directly; Docker runs the Linux image inside a Linux VM. The topology's macOS sections give both execution paths.

| --- | --- |
